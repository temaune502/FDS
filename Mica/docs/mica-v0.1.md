# Mica v0.1: довідник формату

Mica — декларативний формат конфігурації для C-застосунків. Парсер створює AST, але не виконує вирази до першого звернення через API. Значення вузла після успішного обчислення кешується.

## Життєвий цикл

```c
MicaContext *ctx = mica_parse(config_text);
if (mica_last_error(ctx)) {
    fprintf(stderr, "%s\n", mica_last_error(ctx));
}

double fps = mica_get_float(ctx, "app.renderer.target_fps", 60.0);
const char *title = mica_get_string(ctx, "app.ui.window.title", "Application");
int enabled = mica_get_bool(ctx, "app.metrics.enabled", 0);
mica_destroy(ctx);
```

Контекст володіє усім AST, усіма результатами обчислень і рядками інтерполяції. Вказівник, повернений `mica_get_string`, дійсний до `mica_destroy`.

## Інструкції й літерали

Новий рядок або `;` завершують присвоєння. Коментар починається з `//` і тягнеться до кінця рядка. Об'єкти укладаються у `{}`; кома між полями дозволена, але не потрібна.

```mica
name = "Mica"
port = 8080; retries = 3
enabled = true

server = {
    host = "127.0.0.1"
    port = 8080
}
```

Підтримуються числа `double`, `true` / `false`, рядки, raw-рядки та об'єкти. В одному об'єкті повторне присвоєння є перевизначенням: останнє поле має силу.

```mica
policy = { attempts = 2; attempts = 4 } // attempts == 4
message = '''Цей raw-рядок зберігає
нові рядки, "лапки" та ${без інтерполяції}.'''
```

## Пошук і скоупи

Звичайне ім'я шукається у поточному об'єкті, потім у його батьках. Для відносного шляху одна крапка означає поточний об'єкт; кожна наступна підіймає на один рівень.

```mica
app = {
    debug = true
    window = {
        width = 1280
        height = 720
        ratio = .width / .height       // поточний window
        debug_mode = ..debug           // батьківський app
    }
}
```

Це правило відповідає важливій властивості наслідування: вирази всередині об'єкта після `+` перев'язуються до нового об'єкта, а зовнішній лексичний скоуп базового об'єкта зберігається.

## Оператори й порядок пріоритетів

Від найвищого до найнижчого: унарні `-`, `!`; `*`, `/`; `+`, `-`; порівняння `<`, `<=`, `>`, `>=`; рівність `==`, `!=`; `&&`; `||`; тернарний `?:`.

```mica
is_large = .width >= 1920 && .height >= 1080
profile = debug && is_large ? "dev-hq" : "release"
safe = false && (1 / 0 > 0) || true
```

`?:`, `&&` і `||` є лінивими: виконується лише необхідна гілка або частина виразу. Це дозволяє безпечно розміщувати недопустимий вираз у гілці, яка гарантовано не буде обрана.

`+` додає числа або рядки; для двох об'єктів він створює новий об'єкт: поля правого операнда перевизначають поля лівого.

```mica
desktop = base_window + { width = 2560 height = 1440 }
```

## Вбудовані функції

| Функція | Опис |
| --- | --- |
| `clamp(value, low, high)` | Обмежує `value` діапазоном; межі можна передавати у будь-якому порядку. |
| `avg(a, ...)` | Середнє арифметичне одного або кількох чисел. |
| `min(a, ...)`, `max(a, ...)` | Найменше або найбільше з одного чи кількох чисел. |
| `abs(value)` | Абсолютне значення числа. |

## Інтерполяція

У звичайних подвійних лапках `${вираз}` обчислюється під час першого читання самого рядка.

```mica
title = "${.name} — ${.width}x${.height}"
```

Три одинарні лапки створюють raw-рядок. У ньому ні екранування, ні `${...}` не обробляються.

## Помилки, fallback і цикли

Якщо шлях відсутній, операція не має потрібного типу або трапляється ділення на нуль, відповідний вузол переходить у стан `ERROR`, а getter повертає переданий fallback.

Під час обчислення вузол переходить зі стану `UNRESOLVED` у `RESOLVING`. Повторне читання вузла `RESOLVING` означає цикл: runtime записує попередження у `stderr` і повертає fallback поточного запиту. Після успішного обчислення значення переходить у `RESOLVED` і кешується.

## Зміна конфігурації з коду

Setter-и змінюють вихідний текст, а не кешоване значення AST. Після успішної зміни Mica повторно парсить оновлений текст і замінює контекст, тому передавайте адресу вказівника:

```c
MicaContext *ctx = mica_parse(text);

/* Створить відсутнє поле, зберігаючи наявні поля та коментарі. */
MicaSetResult result = mica_set_string(&ctx, "config.input_path", "./src");

/* Якщо немає ні config, ні runtime, буде створена вкладена структура. */
result = mica_set_string(&ctx, "runtime.cache.path", "./cache");
```

Для нового шляху створюються всі відсутні проміжні об'єкти. Якщо проміжний сегмент є числом, рядком або виразом, setter повертає `MICA_SET_INTERMEDIATE_NOT_OBJECT` і нічого не змінює.

Звичайні setter-и замінюють лише літерал того ж типу (`number`, `bool`, звичайний або raw-рядок). Вони повертають `MICA_SET_IS_EXPRESSION` для `${...}`, посилань, викликів функцій, арифметики, merge та тернарних виразів, аби не знищити декларативну логіку помилково. Для свідомої заміни виразу є `mica_set_*_force`.

```c
/* height = .width / 2; не буде перезаписано випадково. */
if (mica_set_float(&ctx, "window.height", 720) == MICA_SET_IS_EXPRESSION) {
    mica_set_float_force(&ctx, "window.height", 720);
}
```

`mica_source(ctx)` повертає поточний текст, який можна записати у файл. При вставленні нових полів зберігається стиль кінців рядків (`LF` або `CRLF`), а заміна значення не зачіпає відступи, коментарі й термінатори навколо нього. Raw-рядок залишається raw-рядком, якщо нове значення не містить `'''`.

## Обмеження v0.1

Формат навмисно не має масивів, підключення файлів, доступу до оточення або довільного виконання коду. Це тримає конфігурацію детермінованою та безпечною. Такі можливості варто проєктувати для наступної версії разом із чіткими правилами ownership і sandboxing.
