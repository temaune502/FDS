# Wi-Fi протокол керування LED-лампою

Це самостійний опис бінарного протоколу керування лампою через Wi-Fi.

Протокол використовує TCP для команд керування і UDP broadcast для пошуку пристроїв у локальній мережі.

## 1. Транспорт

| Параметр | Значення |
|---|---|
| Керування | TCP |
| TCP порт | `5577` |
| Пошук пристроїв | UDP broadcast |
| UDP адреса | `255.255.255.255` |
| UDP порт | `48899` |
| Формат команд | Бінарний масив байтів |
| Кодування команд | Не текстове; передаються raw bytes |
| Довжина команд | Визначається типом кадру |
| Byte order | Багатобайтні числові поля в командах відсутні |
| Роздільник кадрів | Відсутній |

TCP-команда передається без текстового перетворення. Не потрібно додавати `CR`, `LF`, `0x00` або поле довжини.

Одна команда є окремим кадром. Для послідовної передачі кількох кадрів вони можуть іти один за одним, але приймач повинен розпізнавати довжину кожного типу кадру.

## 2. Контрольна сума `CHECKSUM8`

Для кадрів RGB, WW і CW останній байт є контрольною сумою попередніх байтів.

### Формула

```text
CHECKSUM8 = (B0 + B1 + B2 + ... + Bn) & 0xFF
```

де `B0..Bn` це всі байти кадру до checksum.

Checksum не включається сама в суму.

### Приклад

Дані без checksum:

```text
31 FF 00 80 00 0F
```

Розрахунок:

```text
0x31 + 0xFF + 0x00 + 0x80 + 0x00 + 0x0F = 0x1BF
0x1BF & 0xFF = 0xBF
```

Повний кадр:

```text
31 FF 00 80 00 0F BF
```

# 3. Команди живлення

## 3.1 Увімкнення

Повний кадр має 4 байти:

```text
71 23 0F A3
```

| Позиція | Байt | Поле | Опис |
|---:|---:|---|---|
| `0` | `71` | Command | Команда керування живленням |
| `1` | `23` | State | Увімкнути |
| `2` | `0F` | Parameter | Фіксований параметр |
| `3` | `A3` | Checksum/end | Сума перших трьох байтів |

Перевірка:

```text
71 + 23 + 0F = A3
```

## 3.2 Вимкнення

Повний кадр має 4 байти:

```text
71 24 0F A4
```

| Позиція | Байt | Поле | Опис |
|---:|---:|---|---|
| `0` | `71` | Command | Команда керування живленням |
| `1` | `24` | State | Вимкнути |
| `2` | `0F` | Parameter | Фіксований параметр |
| `3` | `A4` | Checksum/end | Сума перших трьох байтів |

Перевірка:

```text
71 + 24 + 0F = A4
```

# 4. RGB

RGB-кадр має 7 байтів:

```text
31 RR GG BB 00 0F SS
```

| Позиція | Поле | Розмір | Значення |
|---:|---|---:|---|
| `0` | Command | 1 байт | `31` |
| `1` | Red | 1 байт | `00..FF` |
| `2` | Green | 1 байт | `00..FF` |
| `3` | Blue | 1 байт | `00..FF` |
| `4` | Reserved | 1 байт | `00` |
| `5` | Mode | 1 байт | `0F` |
| `6` | Checksum | 1 байт | `sum(B0..B5) & FF` |

### Значення RGB

| Десяткове | Hex | Значення |
|---:|---:|---|
| `0` | `00` | Канал вимкнений |
| `1..254` | `01..FE` | Проміжна яскравість |
| `255` | `FF` | Максимальна яскравість |

### Приклади RGB

| Колір | Дані без checksum | Повний кадр |
|---|---|---|
| Червоний `(255,0,0)` | `31 FF 00 00 00 0F` | `31 FF 00 00 00 0F 3F` |
| Зелений `(0,255,0)` | `31 00 FF 00 00 0F` | `31 00 FF 00 00 0F 3F` |
| Синій `(0,0,255)` | `31 00 00 FF 00 0F` | `31 00 00 FF 00 0F 3F` |
| Білий `(255,255,255)` | `31 FF FF FF 00 0F` | `31 FF FF FF 00 0F 3D` |
| Чорний `(0,0,0)` | `31 00 00 00 00 0F` | `31 00 00 00 00 0F 40` |
| Жовтий `(255,255,0)` | `31 FF FF 00 00 0F` | `31 FF FF 00 00 0F 3E` |
| Фіолетовий `(255,0,255)` | `31 FF 00 FF 00 0F` | `31 FF 00 FF 00 0F 3E` |
| Бірюзовий `(0,255,255)` | `31 00 FF FF 00 0F` | `31 00 FF FF 00 0F 3E` |
| `(255,0,128)` | `31 FF 00 80 00 0F` | `31 FF 00 80 00 0F BF` |

### Формат формування

```text
B0 = 31
B1 = Red
B2 = Green
B3 = Blue
B4 = 00
B5 = 0F
B6 = (B0+B1+B2+B3+B4+B5) & FF
```

# 5. Теплий білий `WW`

Кадр має 7 байтів:

```text
31 00 00 00 WW 0F SS
```

| Позиція | Поле | Значення |
|---:|---|---|
| `0` | Command | `31` |
| `1` | Red | `00` |
| `2` | Green | `00` |
| `3` | Blue | `00` |
| `4` | Warm White | `00..FF` |
| `5` | Mode | `0F` |
| `6` | Checksum | `sum(B0..B5) & FF` |

## Перетворення рівня у байт

Якщо рівень задано у відсотках:

```text
WW = round(level * 255 / 100)
```

| Рівень | WW decimal | WW hex |
|---:|---:|---:|
| `0%` | `0` | `00` |
| `25%` | `64` | `40` |
| `50%` | `128` | `80` |
| `75%` | `191` | `BF` |
| `100%` | `255` | `FF` |

## Приклади WW

| Рівень | Повний кадр |
|---:|---|
| `0%` | `31 00 00 00 00 0F 40` |
| `25%` | `31 00 00 00 40 0F 80` |
| `50%` | `31 00 00 00 80 0F C0` |
| `75%` | `31 00 00 00 BF 0F FF` |
| `100%` | `31 00 00 00 FF 0F 3F` |

---

# 6. Холодний білий `CW`

Кадр має 8 байтів:

```text
31 00 00 00 00 CW 0F SS
```

| Позиція | Поле | Значення |
|---:|---|---|
| `0` | Command | `31` |
| `1` | Red | `00` |
| `2` | Green | `00` |
| `3` | Blue | `00` |
| `4` | Warm White | `00` |
| `5` | Cool White | `00..FF` |
| `6` | Mode | `0F` |
| `7` | Checksum | `sum(B0..B6) & FF` |

Перетворення:

```text
CW = round(level * 255 / 100)
```

### Приклади CW

| Рівень | Дані без checksum | Повний кадр |
|---:|---|---|
| `0%` | `31 00 00 00 00 00 0F` | `31 00 00 00 00 00 0F 40` |
| `50%` | `31 00 00 00 00 80 0F` | `31 00 00 00 00 80 0F C0` |
| `100%` | `31 00 00 00 00 FF 0F` | `31 00 00 00 00 FF 0F 3F` |

Підтримка окремого CW-каналу залежить від моделі контролера.

---

# 7. Яскравість

Окремий універсальний кадр яскравості не визначений.

Яскравість RGB формується зміною значень каналів і передачею звичайного RGB-кадру:

```text
R2 = floor(Rbase * level / 100)
G2 = floor(Gbase * level / 100)
B2 = floor(Bbase * level / 100)
```

Після розрахунку надсилається:

```text
31 R2 G2 B2 00 0F SS
```

# 8. Запит стану

Кадр запиту стану має 4 байти:

```text
81 8A 8B 96
```

| Позиція | Байt | Значення |
|---:|---:|---|
| `0` | `81` | Команда запиту стану |
| `1` | `8A` | Фіксований параметр |
| `2` | `8B` | Фіксований параметр |
| `3` | `96` | Фіксований завершальний байт |

Для цього кадру checksum окремо не додається.

---

# 9. Відповідь зі станом

Мінімальний відомий кадр відповіді має 14 байтів:

```text
81 MM PP PR MO SP RR GG BB WW VV CW CM SS
```

| Позиція | Поле | Опис |
|---:|---|---|
| `0` | `81` | Тип відповіді стану |
| `1` | `MM` | Код моделі |
| `2` | `PP` | Код живлення; `23` = ON |
| `3` | `PR` | Preset / effect |
| `4` | `MO` | Режим |
| `5` | `SP` | Швидкість ефекту |
| `6` | `RR` | Червоний канал |
| `7` | `GG` | Зелений канал |
| `8` | `BB` | Синій канал |
| `9` | `WW` | Теплий білий |
| `10` | `VV` | Версія або додаткове поле |
| `11` | `CW` | Холодний білий |
| `12` | `CM` | Режим кольору |
| `13` | `SS` | Контрольна сума або службовий байт |

Стан живлення:

```text
PP == 23  -> ON
PP != 23  -> OFF
```

Точний алгоритм обчислення байта `SS` для відповіді в цій специфікації не фіксується.

# 10. UDP discovery

UDP-пошук не змінює стан лампи. Це broadcast-запит для пошуку IP-адреси пристрою.

| Поле | Значення |
|---|---|
| Адреса | `255.255.255.255` |
| Порт | `48899` |
| Payload ASCII | `HF-A11ASSISTHREAD` |
| Payload hex | `48 46 2D 41 31 31 41 53 53 49 53 54 48 52 45 41 44` |

Відповідь discovery може містити текстову IP-адресу пристрою.

# 11. Зведена таблиця кадрів

| Назва | Довжина | Формат |
|---|---:|---|
| Power ON | 4 | `71 23 0F A3` |
| Power OFF | 4 | `71 24 0F A4` |
| RGB | 7 | `31 RR GG BB 00 0F SS` |

| Cool White | 8 | `31 00 00 00 00 CW 0F SS` |

# 12. Послідовність команд для керування

## Увімкнути

```text
TCP connect(IP, 5577)
SEND: 71 23 0F A3
```

## Вимкнути

```text
TCP connect(IP, 5577)
SEND: 71 24 0F A4
```

## Встановити RGB

Наприклад, для `(255, 0, 128)`:

```text
TCP connect(IP, 5577)
SEND: 31 FF 00 80 00 0F BF
```

## Встановити теплий білий 50%

```text
TCP connect(IP, 5577)
SEND: 31 00 00 00 80 0F C0
```

## Отримати стан

```text
TCP connect(IP, 5577)
SEND: 81 8A 8B 96
RECV: 81 MM PP PR MO SP RR GG BB WW VV CW CM SS
```

# 13. Важливі правила формування кадрів

1. Усі значення каналів передаються одним байтом `00..FF`.
2. У RGB-кадрі порядок каналів: `R`, потім `G`, потім `B`.
3. У WW-кадрі значення теплого білого розташоване на позиції `4`.
4. У CW-кадрі значення холодного білого розташоване на позиції `5`.
5. Поле `0F` має залишатися без змін.
6. Checksum рахується тільки за байтами перед нею.
7. Checksum зберігається у молодшому байті суми.
8. Для ON/OFF використовуються готові 4-байтні кадри.
9. Для status request використовується готовий 4-байтний кадр.
10. Не потрібно додавати довжину, текстові символи або нульовий terminator.
